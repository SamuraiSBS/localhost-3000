Панель помогает маркетологу расставить приоритеты работы с клиентами биллинговой платформы. Она объединяет рейтинг клиентов, причины риска по услугам и денежную оценку ближайших продлений. Изменения данных и коэффициентов автоматически отражаются в интерфейсе.

> **Главное для проверяющего:** запустите приложение, откройте [вход](http://127.0.0.1:8080/login) и пройдите сценарий ниже. Риск — объяснимый индекс внимания, а не статистическая вероятность оттока. Денежные значения API — в **евроцентах**: `100 = €1`.

## Сильные стороны проекта

**От приоритета к действию:** найти клиента → понять причины и деньги → сравнить сценарии → подобрать действие → выгрузить выборку → зафиксировать работу → наблюдать изменения.

Ниже перечислены возможности, найденные в коде текущей рабочей копии, и их практическая польза. Основной MVP и расширения имеют разные срезы проверки и поставки: для Decision Lab и связанных модулей наличие реализации не означает завершение общей приёмки или включение в старый ZIP. Ссылки в таблицах ведут к реализации, контрактам и отчётам, по которым можно проверить каждое преимущество.

### Понятная аналитика для маркетолога

| Преимущество | Польза и реализация |
|---|---|
| Объяснение каждого признака | Вместе со значением хранятся причина, доступность признака и исходные факты. Можно понять, что повлияло на score конкретной услуги. [Реестр признаков](app/domain/features.py) |
| Связь уровня клиента с его услугами | Score клиента определяется наиболее рискованной оцениваемой услугой; карточка раскрывает детали. Это помогает найти конкретный источник риска. [Расчёт](app/domain/scoring.py) |
| Деньги рядом с риском | Оценка учитывает цену продления каждой услуги и её собственный score. Баланс, пополнения и деньги под риском имеют разный смысл. [Денежный расчёт](app/domain/money.py) · [модель](docs/model.md) |
| Рабочий рейтинг | Поиск, фильтр риска, сортировки в обе стороны и пагинация помогают сузить список до нужной группы клиентов. [API рейтинга](app/api/customers.py) |
| Явная неопределённость | Отсутствие оценки и предупреждения о данных видны отдельно; неизвестное значение не превращается в нулевой риск. [Карточка](web/assets/customer.js) · [качество данных](app/data_quality.py) |
| Настройка без изменения кода | Коэффициенты и пороги редактируются в панели, влияют на расчёт и сохраняются в SQLite. [Настройки](app/api/settings.py) |
| Живое обновление | Рейтинг, сводка и график проверяются на согласованность revisions; вкладка обновляется при возврате, polling приостанавливается в фоне. [Интерфейс рейтинга](web/assets/customers.js) |
| График с раскрытой семантикой | Текущие уровни услуг отделены от условного сценария; есть таблица значений и объяснение происхождения рядов. [График](docs/p1-chart.md) |

### Лаборатория решений: проверка действия до применения

| Преимущество | Польза и реализация |
|---|---|
| Один движок для рабочего расчёта и what-if | Изменение весов, дополнительный баланс и переключение автопродления оцениваются теми же правилами. Результаты до/после можно сопоставить на одной базе. [Сценарный расчёт](app/domain/lab.py) |
| Сценарии без записи в рабочую модель | Preview, sensitivity, solver и replay отделены от сохранения настроек и импорта. Можно изучать варианты, сохраняя рабочее состояние. [Реализация API](app/api/lab.py) |
| Анализ чувствительности | Варианты весов и порогов показывают устойчивость score, ранга и категории; для разных сравнений раскрываются свои знаменатели и покрытие. [Sensitivity](app/domain/lab_sensitivity.py) |
| Подбор минимального действия | Solver ищет пополнение и допустимые переключения автопродления для выбранной модельной цели в заданных пределах. Порядок выбора определён: сумма, число переключений, ID услуг. [Solver](app/domain/lab_solver.py) |
| Проверяемая минимальность | Ответ содержит сертификат поиска и проверку суммы на один цент меньше. Состояния «уже достигнуто», «недостижимо» и «исчерпан лимит» различаются. Достижение цели модели не объявляется доказанным удержанием клиента. [Solver](app/domain/lab_solver.py) |
| Ограниченная стоимость расчёта | Поиск имеет бюджет вычислений; календарь — предел событий; импорт, экспорт и кейсы — ограничения размера. При достижении лимита результат явно сообщает об этом. [Solver](app/domain/lab_solver.py) · [календарь](app/domain/renewal_calendar.py) |
| Предпросмотр импорта | До полной замены источника можно увидеть добавленные, исчезнувшие и изменённые записи, предупреждения и влияние на расчёт. [Сравнение снимков](app/domain/lab_source_diff.py) |
| Подтверждение именно просмотренных данных | Запись связывается с preview, checksum и версиями базы. Устаревший preview не применяется; совпадающий снимок обрабатывается как no-op. [API лаборатории](app/api/lab.py) |
| Переносимый паспорт решения | JSON-кейс сохраняет вход расчёта, настройки, время, версии движка и признаков, операцию и ожидаемый результат. Replay пересчитывает его в изоляции. [Формат кейса](app/domain/lab_case.py) |
| Минимизация идентификаторов в кейсе | При экспорте используются синтетические ID, email и названия услуг; транзакции исключаются. Checksum выявляет изменение содержимого. Числовые параметры для воспроизведения расчёта сохраняются. [Экспорт и replay](app/domain/lab_case.py) |

### Практическая работа с клиентами

Эти модули подключены к API и интерфейсу лаборатории в рабочей копии. Их сквозной статус следует оценивать по соответствующему отчёту проверки, отдельно от наличия кода и тестов.

| Преимущество | Польза и реализация |
|---|---|
| Очередь с предметными причинами | Выборка содержит затронутые услуги, сроки, дефицит средств, причины и предполагаемые действия; отдельно доступны сведения о покрытии и исключениях. [Очередь](app/domain/lab_worklist.py) |
| CSV всей выборки | Можно выгрузить полный отфильтрованный список, включая строки за пределами текущей страницы, либо выбранных клиентов очереди. Область, число строк и версии расчёта явно указаны. [API экспорта](app/api/exports.py) |
| Защита CSV от формул | Экспорт учитывает кавычки и переносы строк, использует UTF-8 и помечает опасные начала ячеек как текст. В файл попадают статусы работы; заметки и автор не экспортируются. [Формирование CSV](app/export_csv.py) |
| Учёт работы с клиентом | Статусы «Новый», «В работе», «Отложен», «Обработан», заметка, следующий контакт и ручной исход сохраняются в SQLite. Автор берётся из сессии. [Хранилище работы](app/workflow_storage.py) |
| Защита от потери чужой правки | Запись workflow имеет собственную revision: конкурентное сохранение вызывает конфликт вместо молчаливой перезаписи. [API работы](app/api/workflow.py) · [проверки конфликтов](tests/integration/test_workflow.py) |
| Возврат обработанного клиента при новом риске | Публикация нового источника может повторно открыть обработанную запись при росте уровня риска или появлении дефицита по заданным правилам. Ручное отложение сохраняется; смена весов сама по себе не изображает событие клиента. [Правила возврата](app/workflow_storage.py) |
| Контроль свежести и покрытия | Время получения снимка отделено от времени расчёта. Видны доли клиентов с оценкой score и денег, причины unknown и связанные клиенты; polling не омолаживает источник. [Отчёт качества](app/data_quality.py) |
| Наблюдаемая история | Отдельно фиксируются изменения источника, работы с клиентом и модели. История начинается с включения наблюдения; исчезновение записи не называется доказанным удалением. [API истории](app/api/observations.py) |
| Атомарность истории и публикации | Сохранение наблюдений связано с записью источника; отказ, preview и no-op не должны создавать ложные события. Для этих границ есть интеграционные проверки. [Тесты истории](tests/integration/test_observations.py) |
| Календарь повторных продлений | Отдельный сценарий показывает последовательные платежи, покрытие и первую нехватку средств. Баланс расходуется один раз; учитываются доступность бонусов и календарные границы месяцев. [Календарь](app/domain/renewal_calendar.py) |
| Явные календарные допущения | Неизвестный период не угадывается по цене; пользователь может задать его как допущение. Сценарий повторных оплат не меняет смысл основной оценки ближайшего продления. [Проверки календаря](tests/unit/test_renewal_calendar.py) |

### Точность, согласованность и защита

| Преимущество | Польза и реализация |
|---|---|
| Точные денежные операции | Евроценты, `Decimal`, заданное округление и проверки диапазонов исключают накопление ошибок двоичного float в денежных расчётах. [Деньги](app/domain/money.py) |
| Единый бюджет клиента | Доступные средства распределяются по услугам однократно; заблокированные бонусы и `withdrawBalance` не превращаются автоматически в деньги для оплаты. [Контекст клиента](app/domain/context.py) |
| Согласованный снимок расчёта | Неизменяемая Evaluation связывает данные, настройки и результат. API и Prometheus могут указывать revisions, а интерфейс проверяет их совпадение. [Координатор](app/evaluation.py) · [метрики](app/metrics.py) |
| Контроль конкурирующих изменений | SQLite-транзакции и проверки ожидаемых revisions защищают публикацию источника и настроек. [Хранилище](app/storage.py) |
| Устойчивые черновики | Лаборатория сохраняет ввод при stale/409 и ошибках; запоздалый ответ не должен заменять более новый результат. [Клиент лаборатории](web/assets/lab.js) |
| Защита сессии | Argon2-хеш пароля, непрозрачные HttpOnly/SameSite cookie, ротация сессии и ограничение попыток входа. Secure-флаг зависит от HTTPS origin. [Авторизация](app/auth.py) |
| Защита операций записи | Проверяются сессия, CSRF-токен и точный Origin; предусмотрены ограничения запросов. [Auth middleware](app/auth.py) |
| Отдельный доступ к мониторингу | Bearer token коллектора не заменяет пользовательскую сессию; вход в панель сам по себе не даёт доступ к `/metrics`. [Метрики](app/metrics.py) |
| Настоящий OIDC | Локальный Keycloak, PKCE, state/nonce и проверка подписанного ID token через Authlib; обычный вход доступен независимо от IdP. [OIDC](app/oidc.py) · [запуск](docs/p1-oidc.md) |
| Закрытая локальная конфигурация | Настройщик создаёт случайные секреты, ограничивает доступ к файлам и не перезаписывает существующий каталог конфигурации. [Настройка](scripts/configure_local.py) |

### Decision Lab — расширение в рабочей копии

Раздел `/lab` позволяет сравнить рабочую модель и сценарии, проверить чувствительность к весам, вести очередь клиентов, подобрать действие в заданных пределах, предварительно просмотреть замену источника и экспортировать/повторить кейс. Подтверждение замены источника — отдельная операция записи; расчётные сценарии не меняют рабочую модель.

API и страницы доступны в [OpenAPI](openapi.json); основной пользовательский путь описан в [сценарии демонстрации](docs/demo.md).

## Быстрый запуск

Нужны **Python 3.13**, **Docker Engine** и **Docker Compose ≥ 2.24.4**. Выполняйте команды из корня репозитория. Node.js для основного приложения не требуется.

### Windows / PowerShell

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install --require-hashes -r requirements-dev.txt
.venv/Scripts/python.exe scripts/configure_local.py
powershell -File scripts/dev.ps1 start
```

### Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements-dev.txt
.venv/bin/python scripts/configure_local.py
bash scripts/dev.sh start
```

При настройке задайте логин и пароль; пароль вводится без отображения. Откройте **[http://127.0.0.1:8080/login](http://127.0.0.1:8080/login)** и войдите с этими данными. Общих демонстрационных credentials нет.

| Адрес по умолчанию | Назначение |
|---|---|
| [`/login`](http://127.0.0.1:8080/login) | Вход в продукт |
| [`/customers`](http://127.0.0.1:8080/customers) | Рейтинг и график услуг |
| [`/settings`](http://127.0.0.1:8080/settings) | Коэффициенты модели и источник данных |
| [`/lab`](http://127.0.0.1:8080/lab) | Decision Lab в рабочей копии с расширением |
| [`/api/v1/docs`](http://127.0.0.1:8080/api/v1/docs) | Swagger после входа |
| [`/healthz`](http://127.0.0.1:8080/healthz) | Состояние приложения и версия сборки |

Корневой `/` — отдельная художественная входная сцена; проверку функциональности удобно начинать с `/login`.

Конфигурация создаётся в `.state/local/`: хранится Argon2-хеш пароля и случайный токен мониторинга. Каталог и файлы получают ограниченные права доступа; если их установить нельзя, настройка завершается ошибкой. Существующая конфигурация не перезаписывается. Не включайте `.state/`, секреты и локальные env-файлы в Git или архив сдачи.

<details>
<summary><strong>Управление запуском, другой порт и типовые проблемы</strong></summary>

```powershell
powershell -File scripts/dev.ps1 status
powershell -File scripts/dev.ps1 logs
powershell -File scripts/dev.ps1 stop
powershell -File scripts/dev.ps1 update
```

В Linux/macOS используйте `bash scripts/dev.sh` с теми же действиями. `stop` сохраняет named volume SQLite. Для проверки сохранения настроек перезапускайте тот же Compose project и сохраняйте его volume.

Для отдельного экземпляра на другом порту создайте новую конфигурацию:

```powershell
.venv/Scripts/python.exe scripts/configure_local.py --directory .state/my-demo --origin http://127.0.0.1:8360 --project my-demo
powershell -File scripts/dev.ps1 start -EnvFile .state/my-demo/compose.env
```

Linux/macOS: `bash scripts/dev.sh start .state/my-demo/compose.env`.

- Открывайте точный `PUBLIC_ORIGIN`: `localhost` и `127.0.0.1` — разные origins; несовпадение отклоняется защитой записи.
- Если `.state/local` уже настроен, используйте его либо выберите новый пустой каталог.
- Если Docker сообщает об исчерпанных address pools, проверьте занятые сети и передайте `configure_local.py --subnet` со свободной подсетью для нового project.
- Скрипты явно используют env-файл и `compose.yaml`; старый `compose.override.yaml` не подключается. Корневой `.env` не изменяется.
- Не публикуйте вывод `docker compose config` с секретами; для проверки конфигурации используйте `config --quiet`.

</details>

Дополнительный вход через настоящий локальный Keycloak запускается отдельным Compose overlay/profile: **[инструкция OIDC](docs/p1-oidc.md)**. Обычный вход работает без провайдера.

| 1. Доступ | Откройте `/customers` без сессии, затем войдите через `/login` | Гость направляется на вход; после авторизации доступен рейтинг |
| 2. Приоритет | Найдите клиента, измените сортировку и фильтр риска | Список отражает выбранные условия; видны score и деньги |
| 3. Объяснение | Откройте карточку клиента | Видны услуги, причины риска, доступные средства и денежный смысл оценки |
| 4. Модель | Измените вес активного для клиента признака в настройках | После сохранения score, рейтинг и деньги пересчитываются без ручной перезагрузки |
| 5. Данные | На отдельном тестовом экземпляре импортируйте полный JSON-снимок | Валидные данные обновляют оценку; некорректные отклоняются |

## Как считается риск

Расчёт начинается с услуги. Основные признаки: близость продления, отключённое автопродление, нехватка средств на общую корзину и ожидание оплаты. Веса и пороги редактируются в панели. Клиент получает максимальный score своих оцениваемых услуг; при недостатке данных показывается причина отсутствия оценки.

```text
Score клиента = максимум score оцениваемых услуг
Деньги под риском = сумма (цена ближайшего продления услуги × score услуги / 100)
```

Денежный расчёт использует точную десятичную арифметику и округление по услуге до евроцента. Учитывается одно ближайшее продление каждой подходящей услуги в горизонте модели, по умолчанию 30 суток.

В исходном наборе нет меток оттока и полноценной истории статусов. Поэтому score не является обученной вероятностью, сумма под риском не является MRR, а условный график не изображает реальные исторические отказы. Детали, исключённые статусы и контрольные примеры — в [описании модели](docs/model.md); ограничения источника — в [аудите данных](docs/data-audit.md).

## Устройство проекта

```text
app/                 FastAPI, авторизация, API, расчёты и SQLite
web/                 Рабочие страницы, CSS и ES modules
design/              Токены, foundation, ассеты и дизайн-прототипы
data/seed.json       Синтетический seed для поставки
docs/                ТЗ, модель, архитектура, сценарий и отчёты
tests/               Модульные, интеграционные и браузерные проверки
scripts/             Настройка, запуск, проверки и сборка поставки
infra/               Caddy, мониторинг и инфраструктурные конфигурации
compose.yaml         Основной запуск продукта
openapi.json         Приложенный контракт API
```

Приложение работает с одним Uvicorn worker и одним SQLite volume на Compose project. Контейнер приложения запускается non-root с read-only корневой файловой системой. Зависимости закреплены версиями и хешами в `requirements*.txt`. `infra/probe` — исторический стенд, образ продукта его не запускает.

Клиентский API и Swagger защищены сессией. Запись требует session-bound CSRF token и точного Origin; изменение настроек — актуального `If-Match`. `/metrics` использует отдельный bearer token. Опциональный профиль `monitoring` запускает Prometheus; его UI не публикуется на хост. Подробности — в [контракте API](docs/api-contract.md) и [архитектуре](docs/architecture.md).

## Проверки

Команды ниже предназначены для **полного checkout**. Старые ZIP-пакеты могут не содержать тесты и проверочные скрипты; для них используйте вложенную инструкцию.

```powershell
.venv/Scripts/python.exe scripts/check.py
git diff --check
docker compose --env-file .state/local/compose.env -f compose.yaml config --quiet
.venv/Scripts/python.exe scripts/smoke.py http://127.0.0.1:8080
```

В Linux/macOS замените путь Python на `.venv/bin/python`. `check.py` проверяет целостность дизайна, синтаксис Python и запускает pytest. Smoke проверяет HTTP-доступность и границы доступа; браузерный сценарий проверяется отдельно по [demo](docs/demo.md) и [плану тестирования](docs/test-plan.md).

При сборке `VCS_REF` задаёт версию; по умолчанию она равна `local`. SHA базового commit не идентифицирует незакоммиченные изменения.

<details>
<summary><strong>Изолированная проверка persistence, CSRF и мониторинга</strong></summary>

Создайте новый project и новый каталог. Проверка изменяет тестовые настройки и источник, поэтому её нельзя направлять на рабочую базу.

```powershell
.venv/Scripts/python.exe scripts/configure_local.py --ephemeral --directory .state/delivery-check --origin http://127.0.0.1:8361 --project delivery-check
docker compose --project-name delivery-check --env-file .state/delivery-check/compose.env -f compose.yaml --profile monitoring up -d --build --wait
.venv/Scripts/python.exe scripts/smoke.py http://127.0.0.1:8361 --env-file .state/delivery-check/compose.env --password-file .state/delivery-check/smoke-password
.venv/Scripts/python.exe scripts/verify_delivery.py --project delivery-check --env-file .state/delivery-check/compose.env --password-file .state/delivery-check/smoke-password --url http://127.0.0.1:8361 --revision local --output .state/delivery-check/result.json
```

`--ephemeral` генерирует случайные credentials и приватный password-file для теста. Проверка охватывает повторный вход, CSRF, сохранение данных после restart и настоящий collector.

</details>
