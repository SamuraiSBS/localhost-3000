# Решения

## 2026-10-22 — Подготовка до ТЗ

- Не придумывать продукт и не фиксировать стек. Probe на Python stdlib нужен только для инфраструктуры.
- Репозиторий приватный; видимость не менять.
- Пользователь выбрал будущую VM в Яндекс Облаке и домен `localhost-3000.ru`. VM пока нет; платные ресурсы не создавать.
- Пользователь подтвердил, что корневой домен свободен для проекта; отдельный поддомен не требуется. DNS менять после получения IP новой VM.
- Caddy отвечает за reverse proxy и автоматическое HTTPS после готовности DNS. Сертификаты сохраняются в томе.
- CI и CD разделены. CD принимает артефакт только успешного CI push `main` из этого репозитория; сторонние PR не получают deploy-секреты.
- Сборка маркируется commit SHA; деплой принимает только image digest. GITHUB_TOKEN используется на время workflow, SSH deploy key ограничивается отдельной VM. Docker group даёт фактические root-права, поэтому VM должна быть выделена этому проекту.
- Откат возвращает образ и Compose/Caddy предыдущего релиза. Это не zero-downtime: возможна короткая пауза при пересоздании контейнеров. Миграции/данные потребуют отдельной стратегии после ТЗ.
