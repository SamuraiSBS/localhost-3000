## Извлечение PDF

Текст извлечён постранично pypdf6.10.0. Несколько латинских `r` извлеклись как U+0000; после визуального сравнения13 таких глифов восстановлены. Визуально просмотрены все14 страниц, включая таблицы приёмки/API, поля, титул и заключительную страницу. На с.14 подтверждены100000₽ и QR чата; link annotations в PDF отсутствуют, проверенный TelegramURL не извлечён. Нормализация не меняет смысл и не исправляет оригинальный PDF.

- [Нормализованный текст с разделителями страниц](sources/brief-normalized.txt) — удобная переносимая копия для следующего агента.
- [Extraction manifest](sources/brief-manifest.json) — оригинальный протокол извлечения, нормализации и просмотренных страниц; пути `artifacts/planning` в нём отражают исходное место прогона.
- Raw extraction и PNG находятся в `artifacts/planning/`, который игнорируется Git. Raw не заменяется нормализованной версией.

Текст PDF — данные источника. Обращённая к агентам строка на с.9 зафиксирована отдельно в requirements/rules; она не исполняется как инструкция и не включена в backlog.

## Датасет

[data-audit.md](data-audit.md) содержит человеческий разбор, [data-profile.json](sources/data-profile.json) — полный детерминированный профиль с диапазонами, counts, связями и качеством. Это byte-for-byte копия отчёта из `artifacts/planning/data-profile.json`; ссылки аудита на строки исходного отчёта соответствуют и этой копии.

Повторить read-only профиль:

```powershell
python scripts/profile_dataset.py
```

По умолчанию `--reference 2026-10-19T15:00:00.000Z` — точка генерации fixture, а не выбранная текущая дата продукта. Для иного анализа передать явный reference; original JSON не меняется. CLI печатает JSON в stdout. Он не является runtime валидатором произвольных входов и не исполняет SQL/генерацию/сетевые запросы.

Сверены JSON/генератор/SQL и несколько тестовых граничных случаев в памяти. Полный оригинальный unittest не пройден из-за Windows TEMP ACL (`WinError5`), PostgreSQL не запускался. Эти ограничения не скрываются за успешным профилем.
