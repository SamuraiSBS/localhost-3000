# Возможности и приоритеты

Приоритеты — решение команды по риску доставки, не баллы организатора. Все статусы продукта сейчас **не реализовано**. Источник требований: [requirements](requirements.md); порядок работ: [implementation-plan](implementation-plan.md).

## P0 — допуск и цельная польза

| Возможность | Польза / требование | Как упростить, не потеряв смысл |
|---|---|---|
| Login/password, me/logout, защита UI/API | Без доступа решение не принимается; R-013–016 | Один оператор, серверная сессия, без регистрации/ролей |
| Рейтинг с объяснениями и unknown | «Кому внимание и почему»; R-002–005,017–018 | Native table и карточка; 4×2 обязательных сортировки, один фильтр риска |
| Четыре прозрачных признака | Сразу объяснимый результат; R-037–038 | Registry и чистые функции, без обучения/LLM |
| Стоимость продлений под риском | Бизнес-приоритет и R-008 | Один ближайший период на услугу, cents, явный горизонт и ограничения |
| Редактор коэффициентов, thresholds/H | Проверяемый пересчёт и R-006–007 | Одна форма с server validation и SQLite volume |
| PUT полного snapshot | Новые данные влияют на результат; R-001,022 | Защищённая загрузка JSON без интеграционного брокера |
| Обновление без reload | R-009 | Polling 2 с + versioned coherent Evaluation |
| Prometheus /metrics | R-010,023 | Официальная библиотека, минимум агрегатов, отдельный scrape token |
| Swagger + файл OpenAPI | R-024–025 | Code-first export, локальные assets, точные маршруты |
| Docker Compose + README + модель | R-012,026–029 | Один app+volume, seed только при первом старте |
| Браузерная репетиция и контрольный пример | R-030 | Один понятный клиент, одна правка коэффициента, один изменённый snapshot |

## P1 — преимущества после полностью зелёного P0

| Идея | Почему полезна | Цена/зависимости | Условие включения |
|---|---|---|---|
| Разбор вклада каждого признака | Маркетолог понимает, что привело к score | Уже заложен engine; раскрываемая таблица | Входит в базовые объяснения, визуальный polish после P0 |
| Сортировка по стоимости риска | Приоритизация по денежной величине | Небольшое расширение query/UI | 4 обязательные сортировки уже работают |
| «Что изменилось» после правки | Наглядная чувствительность модели | Сравнение двух согласованных evaluations | Не выдавать сравнение snapshots за исторический backtest |
| График риска/предстоящих непродлений | Прямой бонус R-042 | 2–4 ч ориентировочно, Chart.js, источники рядов | Факт/сценарий различимы; нет выдуманной истории |
| Наблюдения переходов после запуска | Честное начало сбора истории | Малый event log + дедупликация, received time | Подписано «наблюдаемые переходы», не удаление в точный момент |
| Рабочий OIDC | Прямой бонус R-041 | 3–5 ч ориентировочно, Authlib/IdP/callback | Реальный provider и доступ, хватает времени на login/logout/CSRF/state/nonce тесты |
| Экспорт выбранного списка CSV | Полезен маркетологу | 1–2 ч, формулы CSV нейтрализованы | После P0 и если нужен для защиты; не обязательный endpoint |

Часы — прикидка, не обещание и не регламент. Из P1 сначала выбрать **одну** наиболее доказуемую возможность. OIDC без настоящего входа не приносит заявленного результата. График с придуманной историей подрывает обоснованность модели.

## P2 — после хакатона или дополнительных данных

- Обучаемая churn-модель, SHAP, backtest: нужны исходы, история, временной split и задача прогнозирования, которых сейчас нет.
- CRM/рассылки/кампании удержания: ТЗ просит аналитику и выбор клиентов, не автоматическую коммуникацию.
- Управление оплатой/услугами, автосписания, удаление после grace: это функции источника, не анализатора.
- Мультиарендность, команды/права, SSO-платформа Keycloak, очереди/streaming: для текущего объёма нет обоснованной задачи.
- MRR/LTV/прогноз cash flow: нужны дополнительные экономические определения и история; `totalReplenished` не заменяет LTV.
- AI-chat, генерация советов LLM, RAG, векторная БД, «умная» сегментация: не закрывают обязательный путь лучше простого объяснения признаков.

## Чем отличиться в рамках имеющихся данных

Лучшие акценты защиты уже совместимы с P0: одна сумма сходится до цента; два продления не расходуют один баланс дважды; locked бонусы видны отдельно; клиент без данных не маскируется низким риском; нестыковки источника не скрыты; после изменения коэффициента другая вкладка сама обновляется, а настройки переживают restart. Это наблюдаемые свойства продукта, а не заявленные достижения до реализации.
