# Карта дизайна localhost3000

Карта собирается по ответам пользователя до появления ТЗ. Она описывает внешний вид элементов и материалов; продуктовые сценарии определит ТЗ. Числа в таблицах — документация; единственный исполняемый источник значений остаётся `design/tokens.css`.

## Типографика — утверждено 2026-10-22

Единый шрифт **PP Neue Machina Inktrap** для всех элементов. Пользователь выбрал вариант **Б — сдержанная иерархия**.

| Элемент | Размер при базе 16 px | Вес | Высота строки |
|---|---|---|---|
| Главный заголовок | 32 px / 2rem | 500 | 1.25 |
| Заголовок блока | 24 px / 1.5rem | 500 | 1.25 |
| Основной текст | 16 px / 1rem | 400 | 1.65 |
| Кнопка | 16 px / 1rem | 500 | 1.4 |
| Подпись поля | 16 px / 1rem | 500 | 1.65 |
| Поле, меню, полезная подсказка | 16 px / 1rem | 400 | 1.65 |
| Wordmark | Прежние размеры художественной и компактной версий | 600 | SVG-контуры |

Размер существующего вводного текста 20 px сохранён. Трекинг заголовков −0.02em. Кириллица включает Ё/ё; загрузка локальная. Мелкие декоративные подписи запрещены. Браузерное увеличение сохраняется.

## Дизеринг — источник выбран 2026-10-22

Пользователь выбрал [Aceternity UI Dither Shader](https://ui.aceternity.com/components/dither-shader). Основной метод для новых изображений — ordered Bayer; прежний Floyd–Steinberg больше не является вариантом по умолчанию.

Подготовлен [локальный образец](../../design/dither.html) с тем же Bayer/duotone-алгоритмом, адаптированным на native Canvas 2D. Он не выбирает React или стек будущего продукта. Для проекта сохраняется монохром; анимация выключена.

| Параметр | Значение | Статус |
|---|---|---|
| `ditherMode` | `bayer` | Базовый режим выбранного эффекта |
| `colorMode` | `duotone` | Подстроен под существующую палитру |
| Тёмный / светлый цвет дизеринга | `--dither-color-dark` / `--dither-color-light` | Действующие токены; фон исходника задаёт `--color-bg` |
| `gridSize` | **1 CSS px**; в образце доступны 1/2/3 px | **Утверждено пользователем 2026-10-22** |
| `threshold` | **0.50** | **Утверждено пользователем 2026-10-22** |
| `brightness` / `contrast` | 0 / 1 | Нейтральные стартовые значения |
| `pixelRatio` / `animated` | 1 / false | Без дополнительной пикселизации и движения |

Проверяется образец на существующих колоннах, уже содержащих художественный дизеринг. Это не приёмка обработки чистой фотографии. Файлы и композиция главной сцены сохранены. Полный рецепт и ограничения — в [EFFECTS.md](EFFECTS.md).

## Жидкое стекло — утверждено 2026-10-22

Пользователь выбрал [Aceternity UI Liquid Glass](https://ui.aceternity.com/components/liquid-glass) и передал точный пресет **Controls**:

| Параметр | Утверждённое значение |
|---|---|
| `shape` | `circle` |
| `scale` | 50 |
| `aberration` | 20 |
| `bevelDepth` | 60 |
| `frost` | 4.8 |
| `tint` | 0.05 |

Значения по умолчанию хранятся в `--liquid-glass-*` в `design/tokens.css`. [Вызов useDialKit](../../design/tooling/liquid-glass-controls.tsx) с именем `Controls` генерируется из этих токенов. Это готовая конфигурация для React-интеграции, не исполняемый hook текущего native-стенда.

[Локальный образец](../../design/liquid-glass.html) использует те же настройки и исходные SVG/displacement-функции Aceternity через native-адаптер. В Chromium — преломление, в Firefox/WebKit — матовое стекло; reduced transparency/forced colors включают непрозрачную поверхность. Сброс возвращает весь выбранный пресет. Текст и контролы находятся вне линзы.

Пресет заменяет прежние настройки Prism как выбор материала для новых элементов. Существующий WebGL Prism в `index.html` остаётся отдельным ранним прототипом. Форма `circle` относится к этому образцу материала; будущие продуктовые элементы определяются ТЗ. Terminal Bar остаётся плоской.

Уточнение размещения: ориентир — **Hero Section** на той же странице Aceternity. Стекло применяется локально к плавающей панели поверх графики, небольшой плашке и отдельному вторичному действию; главное действие остаётся светлым. Заголовок, обычные карточки и фон секции не становятся стеклянными. В `liquid-glass.html` добавлен отдельный образец этого принципа. Верхняя панель образца не заменяет плоскую Terminal Bar будущей рабочей области. Геометрия адаптирована к нашим токенам: кнопки 2 px, плавающая панель 12 px; круглый пресет отдельной линзы сохранён. Масштабирование при наведении/нажатии из референса не переносится.

## Кнопки — роли, радиус и hover утверждены 2026-10-22

Пользователь отдельно подтвердил: стеклянные кнопки также сохраняют радиус **2 px**, плавающие стеклянные панели — **12 px** (`--radius-floating`). Форма капсулы для них не используется.

- Главное действие — светлая заливка и тёмный текст (`.ds-button`).
- Остальные действия — контурные кнопки с различимой границей (`.ds-button--secondary`).
- Радиус углов обоих вариантов — **2 px** при стандартной базе 16 px (`--radius-control: 0.125rem`).
- Минимальная высота — **48 px**, боковые отступы — **24 px** при стандартной базе 16 px.
- Рамка кнопок и полей — **1 px** в обычном состоянии.
- Наведение — мгновенное монохромное изменение яркости заливки или рамки, без увеличения и сдвига кнопки; длительность **0 ms**.
- Нажатие — мгновенное изменение яркости, без сдвига и уменьшения.

Образец использует `--button-min-height`, `--space-6`, `--border-width` и `--button-hover-duration`. Остальные состояния уточняются отдельно.

## Поля ввода — утверждено 2026-10-22

Тёмный фон, различимый контур 1 px, радиус 2 px и постоянная подпись над полем. Подпись не заменяется placeholder. Размеры в rem сохраняют пользовательское масштабирование.

## Карточки и иконки — утверждено 2026-10-22

Для HackerNoon Pixel Icon Library утверждены варианты: **regular** по умолчанию, **solid** для выбранного состояния. Выбор дополнительно передаётся семантикой (`aria-current`, `aria-pressed` или состоянием соответствующего native-контрола), а не только видом иконки. Конкретные переключаемые элементы определяются после ТЗ.

- Карточки — плоский тёмно-серый фон, прямые углы, без теней.
- Стекло — для плавающих окон и отдельных акцентных элементов с уточнённым выше размещением Hero Section.
- Иконки — **HackerNoon Pixel Icon Library**, выбранная пользователем вместо предложенных тонких контурных иконок. Источник: https://github.com/hackernoon/pixel-icon-library. Подключаются только используемые SVG локально; исходная сетка 24×24, монохромный цвет через CSS mask. Первый включённый образец — regular arrow-right. Происхождение, commit и SHA-256 сохранены в `design/assets/icons/sources.json`; атрибуция и условия доступны в `design/icon-credits.html`.

## Ссылки, фокус, ошибки и отступы — утверждено 2026-10-22

- Ссылки внутри обычного текста постоянно подчёркнуты, а не только при наведении. Ссылки, оформленные кнопками, сохраняют оформление кнопок.
- Клавиатурный фокус — светлый outline **2 px** с отступом **4 px**, через `--focus-width` и `--focus-offset`. Не обрезать рамку контейнером.
- Ошибка поля — монохромная иконка, заметная рамка и понятное пояснение под полем. Причина и способ исправления передаются текстом; `aria-invalid` и `aria-describedby` связывают ошибку с полем. Иконка рядом с пояснением декоративна для скринридера.
- Шкала отступов — **4, 8, 12, 16, 24, 32, 48, 64, 96 px** при стандартной базе 16 px. Использовать существующие `--space-*` из `design/tokens.css`; размеры в rem сохраняют масштабирование.

Фокус, шкала отступов и текстовое подчёркивание уже соответствуют основе. Ошибка в образце поля содержит рамку, связанную подпись и локальную пиксельную иконку HackerNoon.

## Недоступность, загрузка и окна — утверждено 2026-10-22

- Недоступная кнопка получает лёгкий красный оттенок вместо обязательного пояснения причины рядом. Это явное исключение пользователя из монохромной палитры: `--color-disabled-*`. Нативный `disabled` сохраняется, hover/active и выполнение действия отключены. В forced colors используется системное обозначение недоступности. Цвет обозначает состояние, а не объясняет причину.
- Загрузка — текст текущего действия (например, «Сохранение…»), без спиннера. Размер кнопки сохраняется при смене надписи; `aria-busy` сообщает занятость. Не добавлять искусственную задержку. Реальные асинхронные действия появятся после ТЗ; сейчас правило закреплено как контракт.
- Окна появляются коротким проявлением opacity за **150 ms**, без перемещения и масштабирования; при reduced motion — мгновенно. Значение — `--motion-panel`; основу применяет `.ds-dialog[open]` и его backdrop. Закрытие остаётся мгновенным.

## Чекбоксы, подсказки и разделители — утверждено 2026-10-22

- Чекбоксы — квадратные, радиус **2 px**. Выбранное состояние — светлая заливка с тёмной пиксельной галочкой из выбранной библиотеки. Сохранять native input, связанную подпись, управление Space и видимый клавиатурный фокус; область нажатия вместе с подписью не меньше 44×44 CSS px.
- Подсказки — непрозрачный тёмный фон, рамка **1 px**, радиус **2 px**, без стекла. Текст от 16 CSS px. Доступны при фокусе с клавиатуры, а не только при наведении; не содержат единственное объяснение обязательного действия.
- Разделители — тонкие серые линии **1 px**, только между смысловыми блоками. Использовать существующие `--border-width` и `--color-border`; не добавлять декоративную сетку вокруг каждого элемента.

Чекбоксы и подсказка реализованы в `design/preview.html#states`: native checkbox/Space, hover/focus/click и Escape для подсказки. Отдельно показаны regular/solid и загрузка без изменения размеров. Проверки записаны в VERIFICATION.md.

## Изображения — утверждено 2026-10-22

- Дизеринг применяется **ко всем фотографиям**, включая фотографии внутри интерфейса, а не только к художественным изображениям. Использовать выбранный Aceternity Bayer/duotone: точка **1 CSS px**, порог **0.50**. Это правило фотографий; SVG-иконки, текст и интерфейс не растрируются.
- Геометрия изображений — прямые углы, **0 px**, без рамок и теней.
- Изображения статичны: без увеличения при наведении и без параллакса.

Для обработки брать чистый исходник и сохранять оригинал. Уже подготовленные художественные колонны не дизерить повторно; проверка качества выбранного пресета на чистой фотографии остаётся отдельной задачей. Утверждение области применения не означает выполненную пакетную обработку всех ассетов.

## Адаптивность — утверждено 2026-10-22

- На телефоне основные кнопки растягиваются на всю доступную ширину своего контейнера; сохраняются минимальная высота 48 px и боковые отступы 24 px. Это правило главных действий, а не всех ссылок и иконок.
- Фотографии по умолчанию показываются целиком, с сохранением пропорций и без обрезки. Кадрирование — отдельное осознанное исключение по необходимости, а не автоматическое `object-fit: cover` для всех фото.
- На узких экранах сохраняется иерархия **32 / 24 / 16 px** при стандартной базе браузера. Меняются отступы и расположение элементов, а не размер шрифта. Пользовательское масштабирование сохраняется; текст переносится без горизонтального переполнения.

Это утверждённые правила для адаптации компонентов. Существующий Hero-образец уже растягивает главные действия на узком экране; его декоративная подложка колонн служит отдельной художественной композицией. Правило показа фотографий целиком относится к контентным фото и не меняет фоновые художественные сцены автоматически.

## Компоновка — утверждено 2026-10-22

- Между крупными блоками много воздуха: **64–96 px** на широких экранах, **32–48 px** на телефоне, через утверждённые `--space-*`.
- По прямому уточнению пользователя **основная композиция и большинство элементов выравниваются по центру**, а не преимущественно по левому краю. Центрирование не ограничивается художественной главной: распространяется на обычные разделы, заголовки и группы действий.
- Длинные абзацы выравниваются **слева внутри центрированного блока**, с ограниченной длиной строки.
- Формы располагаются **по центру**; подписи и вводимый текст внутри полей выравниваются **слева**.
- Группы кнопок на широком экране — **по центру в ряд**, на телефоне — **друг под другом**. При нехватке ширины допускать перенос без горизонтального переполнения. Главные кнопки на телефоне занимают всю доступную ширину контейнера.
- Обычные разделы имеют плоскую структуру; не оборачивать каждый блок в карточку. Панель используется только при смысловой необходимости.

`design/preview.html` приведён к этим правилам: центрированные разделы и форма, длинный текст слева внутри блока, кнопки в ряд / колонку на телефоне. Другие существующие страницы не объявляются полностью перевёрстанными.

- Контролы и поверхности: остальные состояния кнопок и полей; радиусы остальных поверхностей.
- Анимации: интенсивность реакций за пределами утверждённых мгновенных hover/active кнопок.
