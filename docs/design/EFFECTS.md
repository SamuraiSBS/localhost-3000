# Эффекты и рецепты

Базовые значения находятся в [tokens.css](../../design/tokens.css). Статичная архитектурная графика и реальное оптическое преломление собственной подложки реализованы в `design/index.html`/`prism.js`. Однотонный диалог `preview.html` остаётся примером fallback, а не реализацией оптики.

## Fine Monochrome Dithering

Для статичных колонн выполнена **предварительная подготовка**: ImageGen сразу создаёт качественный исходник с мелким монохромным дизерингом → проверка силуэта → responsive/lossless экспорт Sharp. Во время просмотра дизеринг не пересчитывается. Pillow/Floyd–Steinberg и blue noise остаются рецептами для других исходников, а не фиктивно заявленными шагами обработки нынешнего изображения.

| Метод | Когда подходит | Ограничение |
|---|---|---|
| Floyd–Steinberg / Pillow | Первый вариант для объёма и плавных переходов | Возможны направленные «черви»; оценить силуэт на реальном размере |
| Ordered / Bayer | Детерминированные фактуры с контролируемой структурой | Регулярная сетка может выглядеть как крупный pixel art; не основной выбор |
| Blue-noise threshold | Альтернатива для менее регулярного распределения точек | Нужна проверенная threshold map и её лицензия; масштабирование может дать муар |
| Canvas 2D | Предобработка/небольшой интерактивный участок | Не пересчитывать каждый кадр статичную сцену; pixel data остаются локальными |
| SVG | Wordmark, маски, компактная геометрия и фильтры | Не заменяет художественную архитектуру набором примитивов |
| WebGL/shader | Только согласованная динамическая сцена | Контекст, батарея, DPR и fallback; пока не нужны |

Рецепт для будущего ассета с Pillow (не запущенная финальная обработка):

```python
from PIL import Image, ImageOps

with Image.open("columns-source.png") as source:
    # Сначала композиция и требуемый размер, затем пороговая обработка.
    gray = ImageOps.grayscale(source)
    gray = ImageOps.contain(gray, (1600, 1200), Image.Resampling.LANCZOS)
    dots = gray.convert("1", dither=Image.Dither.FLOYDSTEINBERG)
    ink = ImageOps.colorize(dots.convert("L"), black="#050505", white="#E3E3E3")
    ink.save("columns-dithered.png", optimize=True)
```

В реальном pipeline брать цвета из токенов/передавать параметрами, не заводить вторую палитру. Прозрачный исходник сначала скомпоновать на выбранный фон, иначе прозрачные пиксели дадут неверную яркость. Не применять autocontrast вслепую: он может потерять тёмные объёмы. Размер 1600×1200 — пример, не контракт композиции. Выбрать размеры под фактический макет, подготовить варианты для DPR и `srcset`, проверить точки после ресайза браузером. Не растягивать маленький растр с `image-rendering: pixelated`.

[Pillow](https://pillow.readthedocs.io/en/stable/reference/Image.html) реализует Floyd–Steinberg при переводе в `1`; его enum ORDERED не является готовой Bayer-реализацией. [Christoph Peters](https://momentsingraphics.de/BlueNoise.html) описывает blue-noise threshold textures и важность масштаба. NumPy пригодится для собственной threshold map, но сейчас не требуется ни в приложении, ни в CI.

## Prism Refraction / Liquid Glass

Материал бесцветный, прозрачный, с мягким оптическим краем и локальным разделением белого света. «Liquid» означает плавность поверхности и открытия, а не дымную серую заливку, желе или бесконечное колебание. Простая прозрачность с blur — только упрощение, не полноценный Prism Glass.

Для текущего материала выбран **небольшой WebGL 1 sampler над собственной статичной графикой**, без Three.js и без захвата DOM. Он вычисляет форму скруглённой линзы, смещает выборку изображения, слабо разделяет RGB на краю и добавляет узкий световой блик. Текст и элементы управления остаются обычным DOM. Под текстом shader создаёт мягкое локальное затемнение с растушёвкой; прямоугольной CSS-плашки нет. Направленный нейтральный блик подчёркивает кривизну, дисперсия 0.6 px заметна только на контрастных деталях. Постоянная искусственная радужная рамка исключена. Отрисовка выполняется только при открытии, изменении размеров/режима; постоянного RAF нет. DPR ограничен 1.5, power preference — low-power.

SVG displacement сохранён как альтернатива для подходящих декоративных слоёв. Поддержку `backdrop-filter: url(...)` проверять отдельно: наличие `feDisplacementMap` и положительный `CSS.supports` не доказывают корректную фильтрацию backdrop. [MDN: displacement](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feDisplacementMap), [MDN: backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter), [ограничения WebKit](https://bugs.webkit.org/show_bug.cgi?id=245510).

Рецепт альтернативного SVG-прототипа:

1. Начать с функционального native dialog/панели на непрозрачной поверхности.
2. Для декоративной подложки построить normal/displacement map скруглённой линзы: нейтральный центр, смещение у края, без случайного turbulence на всём экране. Каналы R/G кодируют направления; `feDisplacementMap` ссылается на карту. Масштаб смещения брать из `--glass-displacement`, а не копировать в компоненты.
3. Смещать только видимую подложку/её декоративное представление, не текст и контролы. Разместить световой край отдельным слоем с `pointer-events: none` и `aria-hidden`.
4. Слабо разделить каналы на краю и добавить локальный белый блик. Спектр не окрашивает всю панель и не превышает ориентир 5% площади. Под текстом сохранить достаточный scrim; проверять контраст над светлой и тёмной графикой.
5. Сравнить неподвижный фон через линзу с исходником. Если есть лишь blur и рамка, эффект не принят как refraction.
6. Проверить Chromium, Firefox, Safari; fallback — исходная непрозрачная поверхность. Не включать эксперимент по одному user agent или `CSS.supports`.

Если нужен точно управляемый optical sampler, использовать WebGL над собственной сценой/текстурой. Он не получает произвольный живой DOM как текстуру автоматически. Снимок DOM ради эффекта может ломать доступность, приватность и синхронность — не делать его универсальной архитектурой UI. [Three.js MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html) предлагает transmission/iridescence для 3D, но увеличивает стоимость пикселя; для текущей подготовки не устанавливается.

Текущий материал — визуально убедительная рефракция, не физическая симуляция и не универсальное стекло над произвольным приложением. Для reduced transparency, forced colors, отсутствия WebGL, ошибок shader и потери контекста включается плоский непрозрачный режим. Чекбокс позволяет отключить оптику вручную; функции и текст сохраняются. Потеря контекста проверяется отдельным негативным сценарием. Измерение CPU-времени draw call не выдавать за измерение GPU/frame time.

## Transitions / Motion

CSS достаточно для простых реакций. [Motion](https://motion.dev/docs/quick-start) оценивать после выбора стека для оркестрации состояний; [GSAP](https://gsap.com/docs/v3/GSAP/) — если нужен реальный управляемый timeline. Сейчас ни одна библиотека не установлена.

Вход `ENTER SYSTEM` реализован в нейтральную оболочку: токен 800 ms, 40% на уход сцены и 60% на появление оболочки. Открытие не зависит только от `animationend`: есть ограниченный timeout, reduced motion/скрытая вкладка пропускают движение. Фокус получает заголовок рабочей области; повторное нажатие не запускает второй переход. Browser history отменяет текущую анимацию и восстанавливает нужный экран. Без JS обе области доступны через обычные anchors.

Разрешены короткое проявление графики, изменение opacity и небольшая реакция кнопок. Содержание видно без JS; никакой изначальной невидимости, требующей reveal-класса. Запрещены постоянный glitch, тряска текста, RGB-смещения, массовые частицы, разрушение колонн, избыточный parallax и бесконечные переходы.

## Производительность

Не держать `requestAnimationFrame` для статичного изображения. Для будущей динамики остановка вне viewport/при скрытой вкладке, ограничение DPR (начать с 1.5), не более одной активной стеклянной сцены. Прототип измерять на mobile; при устойчивых кадрах дольше 33 ms снижать качество/включать fallback. Это бюджеты для проверки, не результат измерений.

Растровая сцена: мобильный вариант 303086 bytes укладывается в ориентир 500 KB. Полный 1536px lossless вариант — 1227938 bytes: осознанный компромисс ради мелких точек без lossy-размытия. `srcset` выбирает изображение по viewport/DPR; размер геометрии задан заранее. Сумма WOFF2 — 71736 bytes. Локальные измерения CLS и переходов — в VERIFICATION; реальная мобильная сеть/слабый GPU требуют отдельного устройства. Effects QA включает no-JS, reduced motion/transparency, forced colors и потерю контекста. Критическая функциональность всегда остаётся в семантическом DOM.
