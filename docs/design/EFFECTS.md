# Эффекты и рецепты

Базовые значения находятся в [tokens.css](../../design/tokens.css). Статичная архитектурная графика и реальное оптическое преломление собственной подложки реализованы в `design/index.html`/`prism.js`. Однотонный диалог `preview.html` остаётся примером fallback, а не реализацией оптики.

## Aceternity Floating Dock — мобильная навигация

По прямому запросу пользователя мобильная версия Dashboard использует паттерн [Aceternity Floating Dock](https://ui.aceternity.com/components/floating-dock): кнопка закреплена справа снизу, реальные пункты появляются вертикально над ней. В нативной адаптации используются существующие CSS-токены и локальные HackerNoon Pixel SVG; внешний React/Motion/Tabler runtime не добавляется. Панель использует `--radius-floating`, контролы сохраняют `--radius-control`; нет стекла, тени, увеличения или цветного свечения. Переход короткий, `--motion-panel`, reduced motion отключает его. Кнопка и пункты имеют видимый фокус; названия пунктов видны рядом с иконками в открытой панели, имена ссылок доступны скринридеру. Меню закрывается по Escape и по клику вне панели.

## Fine Monochrome Dithering

По выбору пользователя от 2026-10-22 основной референс и алгоритм для новых изображений — [Aceternity UI Dither Shader](https://ui.aceternity.com/components/dither-shader), ordered Bayer. Это заменяет прежнюю рекомендацию начинать с Floyd–Steinberg. Несмотря на название Shader, опубликованный компонент использует Canvas 2D; WebGL/Three.js для него не нужны.

`design/dither.html` показывает исходник и Bayer/duotone-обработку рядом. `dither.js` адаптирует опубликованные 4×4 Bayer matrix, luminance 0.299/0.587/0.114, brightness/contrast и формулу threshold: `matrixValue * (1 - threshold) + threshold * 0.5`. Это ограниченный native-образец, не полная React-версия со всеми режимами. URL, дата, SHA-256 исходного manual-кода и объём адаптации — в `design/tooling/aceternity-dither.json`. Условия производителя: [licence](https://ui.aceternity.com/licence).

Текущий пресет: `ditherMode="bayer"`, `colorMode="duotone"`, `gridSize=1`, `threshold=0.5`, `brightness=0`, `contrast=1`, `pixelRatio=1`, `invert=false`, `animated=false`, `objectFit="contain"`. Исходник компонуется на `--color-bg`, а цвета дизеринга берутся из `--dither-color-dark`/`--dither-color-light`; числовые настройки — из `--dither-*` в `tokens.css`. Это сохраняет прозрачный фон PNG и поддерживает тёмную и белую версии страниц. **Размер точки 1 CSS px и порог 0.50 утверждены пользователем 2026-10-22**. В образце можно временно сравнить другие настройки; загрузка и сброс возвращают утверждённые 1 px / 0.50.

Отрисовка выполняется при загрузке, изменении размера или параметров, без постоянного RAF. DPR ограничен 2; размер точки задаётся в CSS px. Изображение с осмысленным alt остаётся доступным, декоративный canvas исключён из accessibility tree. Без JS/Canvas 2D показан исходник с пояснением, недоступные настройки скрыты. Reduced motion не запускает движение.

Для статичных колонн ранее выполнена **предварительная подготовка**: ImageGen сразу создал исходник с мелким монохромным дизерингом → проверка силуэта → responsive/lossless экспорт Sharp. Главная сцена по-прежнему использует эти файлы; они не обработаны повторно. Образец Aceternity на колоннах служит сравнению паттернов, а не доказательством качества обработки чистой фотографии. Для новых фотографий нужен недизеренный исходник. Pillow/Floyd–Steinberg и blue noise ниже остаются альтернативными рецептами.

| Метод | Когда подходит | Ограничение |
|---|---|---|
| Ordered / Bayer / Aceternity | Основной выбранный подход; детерминированная фактура | Проверять мелкий размер точек и муар на фактическом CSS-размере; 1/2/3 px сравниваются в образце |
| Floyd–Steinberg / Pillow | Альтернатива для объёма и плавных переходов | Возможны направленные «черви»; применять только при отдельном решении |
| Blue-noise threshold | Альтернатива для менее регулярного распределения точек | Нужна проверенная threshold map и её лицензия; масштабирование может дать муар |
| Canvas 2D | Предобработка/небольшой интерактивный участок | Не пересчитывать каждый кадр статичную сцену; pixel data остаются локальными |
| SVG | Wordmark, маски, компактная геометрия и фильтры | Не заменяет художественную архитектуру набором примитивов |
| WebGL/shader | Только отдельная согласованная динамическая сцена | Для выбранного Aceternity Dither Shader не требуется; его алгоритм работает в Canvas 2D |

Рецепт для будущего ассета с Pillow (не запущенная финальная обработка):

```python
from PIL import Image, ImageOps

with Image.open("columns-source.png") as source:
    # Сначала композиция и требуемый размер, затем пороговая обработка.
    gray = ImageOps.grayscale(source)
    gray = ImageOps.contain(gray, (1600, 1200), Image.Resampling.LANCZOS)
    dots = gray.convert("1", dither=Image.Dither.FLOYDSTEINBERG)
    ink = ImageOps.colorize(dots.convert("L"), black="#050505", white="#E3E3E3")
    ink.save("columns-dithered.png", optimize=True)
```

В реальном pipeline брать цвета из токенов/передавать параметрами, не заводить вторую палитру. Прозрачный исходник сначала скомпоновать на выбранный фон, иначе прозрачные пиксели дадут неверную яркость. Не применять autocontrast вслепую: он может потерять тёмные объёмы. Размер 1600×1200 — пример, не контракт композиции. Выбрать размеры под фактический макет, подготовить варианты для DPR и `srcset`, проверить точки после ресайза браузером. Не растягивать маленький растр с `image-rendering: pixelated`.

[Pillow](https://pillow.readthedocs.io/en/stable/reference/Image.html) реализует Floyd–Steinberg при переводе в `1`; его enum ORDERED не является готовой Bayer-реализацией. [Christoph Peters](https://momentsingraphics.de/BlueNoise.html) описывает blue-noise threshold textures и важность масштаба. NumPy пригодится для собственной threshold map, но сейчас не требуется ни в приложении, ни в CI.

## Aceternity Liquid Glass — выбранный материал

Пользователь выбрал [Liquid Glass от Aceternity](https://ui.aceternity.com/components/liquid-glass) и явно утвердил `Controls`: `shape="circle"`, `scale=50`, `aberration=20`, `bevelDepth=60`, `frost=4.8`, `tint=0.05`. Эти значения приоритетны относительно прежнего Prism-прототипа; не подменять их его параметрами 26/0.6.

Исполняемый источник — `--liquid-glass-*` в `tokens.css`. `scripts/export-liquid-glass.cjs` генерирует `design/tooling/liquid-glass-controls.tsx` с настоящим `useDialKit("Controls", {...})`: для select задаётся `default: "circle"`, для slider tuples первый элемент — утверждённое значение. `--check` проверяет соответствие токенам. React/DialKit не устанавливались; hook — подготовленный адаптер, не запущенный в native-стенде.

`liquid-glass.html`/`liquid-glass.js` используют оригинальные Aceternity displacement-map/SVG-функции из публичной Manual-установки; build-time удалены только TypeScript-аннотации. Исходный SHA-256, дата и границы адаптации записаны в `design/tooling/aceternity-liquid-glass.json`. Нативные контролы показывают тот же пресет, загрузка/сброс его восстанавливают. Круглая линза на собственной графике демонстрирует материал без продуктового сценария. Текст/контролы находятся вне преломляемого слоя.

SVG URL backdrop-filter включается в проверенном Chromium; Firefox/WebKit получают frosted fallback, как описывает производитель. Reduced transparency/forced colors дают непрозрачную поверхность; без JS видны исходная графика и матовый материал, неработающие контролы скрыты. Ошибка Canvas/кодирования карты также включает frosted fallback. Смена предпочтений обрабатывается во время работы; устаревшие blob URL освобождаются. Постоянного RAF нет, DPR карты ограничен 2. `frost=4.8` относится к SVG-фильтру; простой fallback использует предусмотренный исходным компонентом blur 20 px.

### Предыдущий Prism-прототип

Материал бесцветный, прозрачный, с мягким оптическим краем и локальным разделением белого света. «Liquid» означает плавность поверхности и открытия, а не дымную серую заливку, желе или бесконечное колебание. Простая прозрачность с blur — только упрощение, не полноценный Prism Glass.

Для раннего Prism-прототипа был выбран **небольшой WebGL 1 sampler над собственной статичной графикой**, без Three.js и без захвата DOM. Он вычисляет форму скруглённой линзы, смещает выборку изображения, слабо разделяет RGB на краю и добавляет узкий световой блик. Текст и элементы управления остаются обычным DOM. Под текстом shader создаёт мягкое локальное затемнение с растушёвкой; прямоугольной CSS-плашки нет. Направленный нейтральный блик подчёркивает кривизну, дисперсия 0.6 px заметна только на контрастных деталях. Постоянная искусственная радужная рамка исключена. Отрисовка выполняется только при открытии, изменении размеров/режима; постоянного RAF нет. DPR ограничен 1.5, power preference — low-power.

SVG displacement сохранён как альтернатива для подходящих декоративных слоёв. Поддержку `backdrop-filter: url(...)` проверять отдельно: наличие `feDisplacementMap` и положительный `CSS.supports` не доказывают корректную фильтрацию backdrop. [MDN: displacement](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feDisplacementMap), [MDN: backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter), [ограничения WebKit](https://bugs.webkit.org/show_bug.cgi?id=245510).

Рецепт альтернативного SVG-прототипа:

1. Начать с функционального native dialog/панели на непрозрачной поверхности.
2. Для декоративной подложки построить normal/displacement map скруглённой линзы: нейтральный центр, смещение у края, без случайного turbulence на всём экране. Каналы R/G кодируют направления; `feDisplacementMap` ссылается на карту. Масштаб смещения брать из `--glass-displacement`, а не копировать в компоненты.
3. Смещать только видимую подложку/её декоративное представление, не текст и контролы. Разместить световой край отдельным слоем с `pointer-events: none` и `aria-hidden`.
4. Слабо разделить каналы на краю и добавить локальный белый блик. Спектр не окрашивает всю панель и не превышает ориентир 5% площади. Под текстом сохранить достаточный scrim; проверять контраст над светлой и тёмной графикой.
5. Сравнить неподвижный фон через линзу с исходником. Если есть лишь blur и рамка, эффект не принят как refraction.
6. Проверить Chromium, Firefox, Safari; fallback — исходная непрозрачная поверхность. Не включать эксперимент по одному user agent или `CSS.supports`.

Если нужен точно управляемый optical sampler, использовать WebGL над собственной сценой/текстурой. Он не получает произвольный живой DOM как текстуру автоматически. Снимок DOM ради эффекта может ломать доступность, приватность и синхронность — не делать его универсальной архитектурой UI. [Three.js MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html) предлагает transmission/iridescence для 3D, но увеличивает стоимость пикселя; для текущей подготовки не устанавливается.

Ранний Prism-прототип — визуально убедительная рефракция, не физическая симуляция и не универсальное стекло над произвольным приложением. Для reduced transparency, forced colors, отсутствия WebGL, ошибок shader и потери контекста включается плоский непрозрачный режим. Чекбокс позволяет отключить оптику вручную; функции и текст сохраняются. Потеря контекста проверяется отдельным негативным сценарием. Измерение CPU-времени draw call не выдавать за измерение GPU/frame time.

## Transitions / Motion

Уточнение пользователя по изображениям: выбранный Aceternity Bayer/duotone (1 CSS px / 0.50) применяется ко всем фотографиям, не только художественным. Прямые углы 0 px, без рамок и теней; без hover-scale и параллакса. SVG-иконки и текст сохраняют своё представление. Сохранять чистые оригиналы и не повторять обработку уже дизеренных колонн. Проверка чистого фотографического исходника ещё требуется.

Пользователь утвердил мгновенные hover/active кнопок: изменение яркости без сдвига и scale. `--button-hover-duration: 0ms` отделён от анимации входа и панелей.

Размещение выбранного Liquid Glass уточнено по Hero Section Aceternity: локальная плавающая панель, компактная плашка и вторичное действие над графикой. Native-образец `liquid-glass.html` использует исходный SVG-алгоритм и общие Controls; радиус новых поверхностей читается из CSS, bevel ограничен радиусом. Текст находится в DOM поверх оптического слоя, под текстом предусмотрен тёмный scrim. Кнопка главной фото-сцены использует Liquid Glass по отдельному запросу пользователя; обычные карточки плоские, Terminal Bar рабочей области не заменяется плавающей панелью.

По прямому запросу пользователя кнопка `CONNECT` на главной использует этот же материал поверх фотографии. Видимый текст остаётся отдельным HTML-слоем; Chromium получает SVG-преломление с радиусом кнопки, остальные браузеры — матовый вариант, а reduced transparency/forced colors — непрозрачный fallback.

CSS достаточно для простых реакций. [Motion](https://motion.dev/docs/quick-start) оценивать после выбора стека для оркестрации состояний; [GSAP](https://gsap.com/docs/v3/GSAP/) — если нужен реальный управляемый timeline. Сейчас ни одна библиотека не установлена.

`CONNECT` ведёт на статичную страницу входа; оттуда обычные ссылки переключают вход и регистрацию. На обеих страницах переиспользуются фон и Bayer-дизеринг главной, а кнопки формы (отправка и показ пароля) используют Liquid Glass с теми же fallback. Клиентская проверка ограничена обязательностью полей, форматом почты и совпадением паролей; требования к сложности пароля не вводятся до ТЗ. У форм пока нет backend и отправки данных. Нейтральная оболочка главной доступна отдельно по `#workspace`; её hash-переход сохраняет прежнюю поддержку истории и клавиатурного фокуса.

Разрешены короткое проявление графики, изменение opacity и небольшая реакция кнопок. Содержание видно без JS; никакой изначальной невидимости, требующей reveal-класса. Запрещены постоянный glitch, тряска текста, RGB-смещения, массовые частицы, разрушение колонн, избыточный parallax и бесконечные переходы.

## Производительность

Не держать `requestAnimationFrame` для статичного изображения. Для будущей динамики остановка вне viewport/при скрытой вкладке, ограничение DPR (начать с 1.5), не более одной активной стеклянной сцены. Прототип измерять на mobile; при устойчивых кадрах дольше 33 ms снижать качество/включать fallback. Это бюджеты для проверки, не результат измерений.

Растровая сцена: мобильный вариант 303086 bytes укладывается в ориентир 500 KB. Полный 1536px lossless вариант — 1227938 bytes: осознанный компромисс ради мелких точек без lossy-размытия. `srcset` выбирает изображение по viewport/DPR; размер геометрии задан заранее. Сумма WOFF2 — 146188 bytes. Локальные измерения CLS и переходов — в VERIFICATION; реальная мобильная сеть/слабый GPU требуют отдельного устройства. Effects QA включает no-JS, reduced motion/transparency, forced colors и потерю контекста. Критическая функциональность всегда остаётся в семантическом DOM.
