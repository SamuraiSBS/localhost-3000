# Основа дизайн-системы

## Принципы

Digital Ruins / Lost Signal соединяет Digital Solitude, Post-Internet, Corrupted Architecture, Terminal Nostalgia и Digital Archaeology с редким Prism Refraction. Ориентир — 80% ретро / 20% современность: характер через графику и геометрию, удобство через аккуратную типографику и поведение.

Основу составляют почти чёрный фон, светлый текст, большое количество пустоты, тонкие линии и одна сильная композиция. Рабочие экраны следуют принципу Retro Shell / Modern Core. Предметная область пока неизвестна.

## Цвета

Исполняемый источник — [tokens.css](../../design/tokens.css). Значения ниже фиксируют утверждённую палитру, не являются отдельной конфигурацией.

| Роль | Цвет | Токен |
|---|---|---|
| Фон | `#050505` | `--color-bg` |
| Поверхность | `#141414` | `--color-surface` |
| Вторичная поверхность | `#242424` | `--color-surface-raised` |
| Структурная линия | `#343434` | `--color-border` |
| Основной текст | `#F1F1F1` | `--color-text` |
| Вторичный текст | `#9D9D9D` | `--color-text-secondary` |
| Светлая графика | `#E3E3E3` | `--color-art` |

Для фото на `/` и страницах авторизации Bayer/duotone использует чёрную подложку страницы и чисто-белый светлый тон камня через `--dither-color-dark`/`--dither-color-light`. Основная палитра интерфейса остаётся почти чёрной.

Промежуточный серый `--color-border-control` нужен для различимых границ полей. Структурная линия не используется как единственная граница интерактивного элемента. Фокус светлый, заметный и не зависит от радуги.

Около 95% видимой площади — монохром. До 5% может занимать призматический спектр: красный → оранжевый → жёлтый → зелёный → голубой → синий → фиолетовый как разделение белого света. Он живёт на краях стекла и в отдельных взаимодействиях. Токены спектра — опорные цвета для оптики, не готовый CSS-градиент для заливки кнопок.

Не использовать синюю основу тёмной темы, цветные CTA, большие цветные поверхности, градиентный текст или постоянное радужное свечение. Ошибки передавать словом, значком и границей; не только цветом.

## Типографика

- **PP Neue Machina Inktrap** — единое семейство для заголовков, меню, текста, кнопок, карточек, форм и основы wordmark. Прямое уточнение пользователя от 2026-10-22 заменяет прежний выбор JetBrains Mono. Использовать именно Inktrap, не Plain.
- Основной текст — normal 400; кнопки и заголовки — 500, контуры wordmark — 600. Не превращать каждый заголовок в жирный display.
- Основной размер и полезные подписи — не меньше `1rem` при стандартной базе 16 px; высота строки 1.65. Не уменьшать корневой размер браузера. Текст 10–13 px запрещён.
- Пользователь утвердил **вариант Б**: главный заголовок `--type-title` — 2rem (32 px), заголовок блока `--type-heading` — 1.5rem (24 px), основной текст `--type-body` — 1rem (16 px). Это единые размеры при стандартной базе, без локальных fluid-переопределений; браузерное масштабирование сохраняется. Трекинг заголовков −0.02em. Строка текста — до 68ch. Основная композиция центрирована; длинный текст выравнивается слева внутри центрированного блока по уточнению пользователя.
- Сохранять масштабирование и переносы; длинные слова/URL не должны ломать экран. `text-wrap: balance` для заголовков, `pretty` для прозы.

Файл [PP Neue Machina Inktrap](https://pangrampangram.com/products/neue-machina) включён локально в `design/assets/fonts` и подключается через `design/fonts.css`. Официальный URL и SHA-256 сохранены рядом в `sources.json`; условия локальной подготовки описаны в `assets/fonts/README.md`. Это proprietary-шрифт, не OFL. Проверка исходного cmap охватывает все 33 русские буквы в обоих регистрах, включая `Ёё`.

Self-host, `font-display: swap`; один variable WOFF2 без изменения исходных байтов, диапазон 100–900. Размер — 146188 bytes, ниже бюджета 200 KB. Официальный URL заканчивается на `.woff`, но payload имеет сигнатуру WOFF2 и сохранён с корректным расширением `.woff2`. Внешних runtime font CDN нет. Fallback: Arial → sans-serif. Прежний `@font-face`, preload, моноширинные fallback и файлы JetBrains удалены. При изменениях повторять проверки глифов, загрузки, отказа сети и сдвига макета.

## Размеры и сетка

Последнее уточнение пользователя: основная композиция и большинство элементов по центру, включая обычные разделы, заголовки и группы действий. Центрирование не ограничивается художественной главной. Длинный текст выравнивается слева внутри центрированного блока; формы центрированы, подписи и вводимый текст слева. Группы кнопок на широком экране центрированы в ряд, на телефоне расположены друг под другом. Между крупными блоками 64–96 px на широких экранах, 32–48 px на телефоне. Структура плоская, без карточки вокруг каждого блока.

Шаги отступов: 4, 8, 12, 16, 24, 32, 48, 64, 96 px через `--space-*`. Плотность определяется задачей, а не равномерным заполнением пустоты. Рабочая область до 76rem, проза до 68ch; поля экрана плавно меняются от 16 до 48 px. Одномерные группы — Flex; двумерные данные — Grid.

Панели преимущественно прямоугольные. Радиусы: 0 для плоскостей, 2 px для контролов, 12 px для плавающей панели, 24 px для оптической линзы. Тонкая рамка без широкой декоративной тени. Минимальная интерактивная область — 44×44 CSS px; на телефоне не уменьшать её.

## Состояния и слои

| Состояние | Поведение |
|---|---|
| Default | Читаемый текст, различимый контрол |
| Hover | Небольшая монохромная смена поверхности; информация доступна и без hover |
| Focus-visible | Светлый outline 2 px с отступом 4 px, не обрезан контейнером |
| Active | Краткая реакция; выбранный пункт дополнительно отмечен `aria-current` |
| Disabled | Семантический `disabled`, лёгкий красный оттенок кнопки, без hover/active и обработки нажатий; по уточнению пользователя обязательной причины рядом нет |
| Invalid | Текст причины и способ исправить, `aria-invalid`, связь `aria-describedby` |
| Loading | Текст текущего действия, без спиннера и изменения размера кнопки, `aria-busy`; не выдумывать проценты |

Слои задаются семантически: base → dropdown → sticky → backdrop → modal → toast → tooltip. Нативный `<dialog>` использует top layer, а не соревнование z-index. Выпадающие панели не обрезать `overflow`; использовать native popover/dialog или portal будущего стека.

## Адаптивность и движение

Пользователь утвердил: на телефоне основные кнопки занимают всю доступную ширину контейнера; контентные фотографии по умолчанию видны целиком без обрезки и с сохранением пропорций. На узких экранах остаётся типографика 32/24/16 px при стандартной базе, адаптируются отступы и расположение. Сохранять масштабирование браузера и переносы. Декоративные фоновые композиции не являются контентными фотографиями.

Проверять минимум 360, 768 и 1440 CSS px, дополнительно 320 px и увеличение до 200%. Это проверочные точки, не обязательные CSS-breakpoints. Панель навигации переносится или получает осмысленное мобильное раскрытие; контент перестраивается в одну колонку. Не масштабировать весь интерфейс вниз и не прятать важные действия.

Hover/active кнопок мгновенные, появление окон 150 ms, вход в систему 800 ms. Для остальных коротких реакций сохранён токен 140 ms. Easing — спокойный ease-out; без bounce. Reduced motion делает переходы мгновенными, без ожидания таймера. Контент видим по умолчанию; отсутствие JS/анимации не оставляет пустой экран. Подробнее: [EFFECTS.md](EFFECTS.md).

## Антипримеры

Декоративные `SYS_001`, `SYSTEM ONLINE`, `PORT 3000`, координаты курсора, номера секций и бессмысленные английские фразы запрещены как паттерн, а не только как перечисленные слова. Также запрещены микроподписи над каждым заголовком, одинаковые карточки ради заполнения, сайдбар по умолчанию, повсеместное стекло, крупный пиксель-арт вместо точечного дизеринга, агрессивный RGB-глитч и «терминал» из нечитаемых надписей.
