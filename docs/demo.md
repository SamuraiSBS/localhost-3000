## История для жюри

«Маркетологу нужен понятный приоритет: кому уделить внимание, по какой причине и какая стоимость продления под риском. Наш анализатор считает это по текущим услугам и доступным средствам; не выдаёт синтетический набор за обученную модель».

| Время, ориентир | Действие | Что доказываем |
|---|---|---|
| 0:00–0:30 | Войти обычным логином/паролем, открыть рейтинг | Доступ защищён, основные показатели читаемы |
| 0:30–1:20 | Найти контрольного клиента, открыть его услуги | Score/уровень/конкретные причины; cents/€ и горизонт |
| 1:20–2:10 | Показать корзину и ручную формулу | Цена, баланс и риск учтены; одни деньги не покрывают два платежа |
| 2:10–2:50 | Изменить один коэффициент, держать рядом вторую вкладку | Score, порядок и сумма обновились без reload |
| 2:50–3:20 | Загрузить изменённый snapshot либо показать подготовленный feeder | Это динамический расчёт, исходные данные меняют вывод |
| 3:20–4:00 | Settings после restart, /metrics и Swagger, кратко extension | Persistence, обязательный контракт, расширяемость и воспроизводимый Compose |

Restart и проверки API можно показать коротким заранее подготовленным доказательством той же revision, если live restart не помещается в тайминг; полную проверку выполнить до защиты. Видео/скриншот — резерв/доказательство прогона, не замена работающему приложению.

## Отдельная инфраструктурная приёмка probe

Исторический справочник прежней подготовки, **не шаги текущей репетиции/реализации MVP**. Не менять probe, не запускать CI/CD, публичный релиз или rollback по этому разделу без соответствующего поручения и актуального release-контекста. Продуктовая приёмка описана выше.

1. Открыть страницу и убедиться в тексте `localhost-3000 — Infrastructure Ready`.
2. Проверить `/healthz` и точный commit SHA, а не только HTTP 200.
3. Пройти smoke в контейнерах и через публичный URL с валидным TLS.
4. Изменить видимый текст probe, сделать отдельный коммит, дождаться CI/CD; проверить текст и новый SHA извне.
5. В контролируемом тесте подтвердить возврат к предыдущему SHA после плохого релиза.

Инфраструктурный probe не доказывает готовность продукта. Браузерные проверки основного продукта, мобильная вёрстка, реальные интеграции и репетиция жюри выполняются после реализации MVP.
