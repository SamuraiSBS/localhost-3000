# Демонстрация

Статус на 2026-10-23: сценарий подготовлен по ТЗ с. 12; **репетиция продукта не выполнена**. Продолжительность защиты неизвестна (Q-004). Ниже предлагается основной рассказ на 4 минуты, который нужно сократить/расширить под ответ организатора.

## История для жюри

«Маркетологу нужен понятный приоритет: кому уделить внимание, по какой причине и какая стоимость продления под риском. Наш анализатор считает это по текущим услугам и доступным средствам; не выдаёт синтетический набор за обученную модель».

| Время, ориентир | Действие | Что доказываем |
|---|---|---|
| 0:00–0:30 | Войти обычным логином/паролем, открыть рейтинг | Доступ защищён, основные показатели читаемы |
| 0:30–1:20 | Найти контрольного клиента, открыть его услуги | Score/уровень/конкретные причины; cents/€ и горизонт |
| 1:20–2:10 | Показать корзину и ручную формулу | Цена, баланс и риск учтены; одни деньги не покрывают два платежа |
| 2:10–2:50 | Изменить один коэффициент, держать рядом вторую вкладку | Score, порядок и сумма обновились без reload |
| 2:50–3:20 | Загрузить изменённый snapshot либо показать подготовленный feeder | Это динамический расчёт, исходные данные меняют вывод |
| 3:20–4:00 | Settings после restart, /metrics и Swagger, кратко extension | Persistence, обязательный контракт, расширяемость и воспроизводимый Compose |

Restart и проверки API можно показать коротким заранее подготовленным доказательством той же revision, если live restart не помещается в тайминг; полную проверку выполнить до защиты. Видео/скриншот — резерв/доказательство прогона, не замена работающему приложению.

## Данные для наглядного показа

Использовать предоставленный набор как базу. Оригинал `материалы/data/data.json` не менять. При реализации отдельно сохранить `demo/source-base.json` и `demo/source-changed.json` с явно помеченными дополнительными синтетическими клиентами, ID вне исходных диапазонов, фиктивные email `@example.test`.

Самый надёжный контрольный клиент — M02 из [model](model.md): услуга1 000cents, доступно1 000cents, active, auto=false, срок наступает в явный demo as_of, веса20/25/35/20. Score45,medium, сумма450cents. Изменить manual_renewal25→50: score70,high,700cents. Это выбор подходящего примера чувствительности; не обещать эффект изменения веса у клиента с уже насыщенным score100.

Для live now подготовить дату окончания относительно запуска и сверить ожидаемое значение по фактическому `as_of`; точное45/70 верно на указанной границе. Для фиксированного replay прямо показать дату в панели. Не замораживать часы молча. Дополнительные случаи: M09 unknown, M10 общий баланс двух услуг, M06/M07 бонусы.

`source-changed` меняет только конкретные финансовые/сервисные поля выбранного demo клиента, чтобы он поменял место рейтинга и деньги. Имена/ID/счётчики не должны быть единственной причиной изменения. Вторая открытая вкладка сама обновляется в локальной проверочной цели<=5с.

## Репетиция перед передачей

Пройти A-01–A-12 из [evaluation](evaluation.md), browser сценарий [test-plan](test-plan.md) на 360 и1440px, затем клавиатуру/320px/200% zoom по design QA. Подготовить отдельный Compose project для чистого запуска; не удалять пользовательский volume. Убедиться, что persistence проверена **с сохранённым** томом.

Проверить браузером вход/рейтинг/карточку/settings/PUT, 8 сортировок и фильтр, неизвестного клиента/отсутствие оценки, logout. Сверить метрики и деньги той же evaluation, наличие OpenAPI-файла и local Swagger без CDN. Записать revision, hashes входных снимков, настройки и ограничения.

Дополнительную OIDC кнопку показывать только после настоящего входа; график — только с различимыми фактом/сценарием. Для исходного набора честно сказать: «Истории удалений нет». Не рисовать прошлый отток из текущих deleted и не обещать статистическую точность модели.

## Если сеть недоступна

Основная панель, seed, пароли, docs и расчёты работают локально через Compose; runtime assets обслуживаются из образа. OIDC может быть недоступен — использовать обязательный локальный вход. Заранее сохранить резервную запись реально пройденного сценария и локальный адрес запуска, не выдавать запись за текущий live.

## Отдельная инфраструктурная приёмка probe

Исторический справочник прежней подготовки, **не шаги текущей репетиции/реализации MVP**. Не менять probe, не запускать CI/CD, публичный релиз или rollback по этому разделу без соответствующего поручения и актуального release-контекста. Продуктовая приёмка описана выше.

1. Открыть страницу и убедиться в тексте `localhost-3000 — Infrastructure Ready`.
2. Проверить `/healthz` и точный commit SHA, а не только HTTP 200.
3. Пройти smoke в контейнерах и через публичный URL с валидным TLS.
4. Изменить видимый текст probe, сделать отдельный коммит, дождаться CI/CD; проверить текст и новый SHA извне.
5. В контролируемом тесте подтвердить возврат к предыдущему SHA после плохого релиза.

Инфраструктурный probe не доказывает готовность продукта. Браузерные проверки основного продукта, мобильная вёрстка, реальные интеграции и репетиция жюри выполняются после реализации MVP.
