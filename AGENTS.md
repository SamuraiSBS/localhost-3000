# Lazyum Autumn Hack

- До появления ТЗ готовим только инфраструктуру. `infra/probe` — заменяемый стенд, не выбранный стек продукта.
- После получения ТЗ сначала заполнить `docs/challenge.md`, `rules.md`, `evaluation.md`; проверить допустимость заранее подготовленного кода. Затем выбрать простой стек под критерии и определить работающий MVP.
- Сначала основной пользовательский сценарий и критерии жюри, затем дополнительные возможности. Новые сервисы и зависимости должны решать конкретную задачу.
- Перед изменениями проверить `git status`, прочитать относящиеся документы; сохранять чужие изменения. Не удалять файлы без понятной причины, не использовать destructive reset/clean.
- Исправлять обнаруженные ошибки в рамках задачи. После существенных изменений запускать подходящие тесты; перед коммитом `python scripts/check.py` и `git diff --check`. Сохранять проект запускаемым.
- Использовать короткие ветки `feat/*`, `fix/*`, `infra/*`, `docs/*`, небольшие осмысленные коммиты и PR с описанием результата и проверок. Основная ветка — `main`.
- Секреты только в локальном `.env`, SSH-agent или GitHub Secrets. `.env.example` содержит безопасные значения. Не выводить токены, приватные ключи и полные окружения.
- Документировать существенные решения в `docs/decisions.md`, состояние инфраструктуры — в `docs/infrastructure.md`; поддерживать инструкции запуска при изменениях.
- Для браузерных сценариев использовать доступный browser tool; API-проверки не заменяют E2E. Перед защитой пройти `docs/demo.md` и ключевой сценарий на узком и широком экранах.
- Отличать подготовленную конфигурацию от выполненной проверки. CI, Docker, VPS, HTTPS и публичный E2E отмечать отдельно, с фактическими доказательствами.
- Не покупать ресурсы, не менять видимость репозитория, DNS и защиту доступа без соответствующего контекста и полномочий. Не отключать защиту ради прохождения проверки.

Локальные навыки находятся в `.agents/skills/`: `hackathon-planner`, `mvp-builder`, `devops-deploy`, `demo-qa`. Использовать по назначению; они дополняют эти правила проектными процедурами.
